# INFORME TÉCNICO: RUTA DE DATOS Y DECODIFICACIÓN DE LA INSTRUCCIÓN LW (LOAD WORD)

## 1. Introducción y Propósito del Circuito
El circuito diseñado en CircuitVerse representa la ruta de datos completa y el sistema de control básico para la ejecución de la instrucción LW (Load Word) en una arquitectura segmentada de 16 bits. El propósito principal de este bloque es calcular una dirección efectiva en la memoria RAM de datos, acceder a dicha posición en modo lectura y almacenar el valor resultante en un registro de destino. Matemáticamente, la instrucción opera sumando el contenido del Registro Base con el valor de Offset para establecer la Dirección Efectiva, utilizándola inmediatamente como puntero para transferir el contenido de la Memoria RAM hacia el Registro Destino.

## 2. Unidad de Decodificación (Lógica de Control)
El circuito cuenta con un módulo de decodificación de OpCode encargado de habilitar el andamiaje del sistema de manera automática. El origen de los datos proviene de los 4 bits más significativos de la instrucción binaria. Para la instrucción LW, el código asignado en la arquitectura es el binario 0010, que equivale al número 2 en decimal. Con respecto a la implementación de hardware, se diseñó un decodificador digital utilizando una compuerta AND de 4 entradas combinada con 3 compuertas NOT conectadas a los bits que deben ingresar en estado bajo. En cuanto al funcionamiento, la línea de control maestro solo se elevará a un 1 lógico (verde brillante) cuando detecte la combinación exacta 0010, de modo que cualquier otro OpCode inhabilitará la salida. Esto protege los registros de escrituras accidentales y actúa como la señal de Enable para los componentes de la ruta de datos.

## 3. Banco de Registros de 16 bits (Implementación Modular)
Para respetar las condiciones de diseño a bajo nivel sin sobrecargar el lienzo de cables, el almacenamiento se estructuró mediante subcircuitos jerárquicos. La estructura interna hecha a mano consta de un bloque base que funciona como un subcircuito de 8 bits conformado por 8 flip-flops tipo D interconectados a nivel de compuertas individuales. Para el escalamiento a 16 bits, se acoplaron dos de estos subcircuitos de 8 bits operando en paralelo. Ambos comparten de forma síncrona tanto la señal de Reloj general del sistema como la señal de habilitación provista por el decodificador de OpCode. A través de este flujo de datos, el Registro Base recibe la Entrada Inicial de 16 bits mientras que el Registro de Salida recibe el dato proveniente de la RAM, logrando que los 16 bits se congelen en paralelo de manera limpia al recibir el flanco ascendente del reloj.

## 4. Unidad Aritmética: Sumador de 16 bits (Ripple Carry)
El cálculo de la dirección de memoria se realiza a través de un Sumador por Propagación de Acarreo (Ripple Carry Adder) de 16 bits diseñado de manera modular. Su arquitectura interna está construida a partir de dos subcircuitos sumadores de 8 bits, los cuales contienen la lógica de sumadores completos de 1 bit con compuertas XOR, AND y OR. Para lograr la extensión a 16 bits, se realizó el puente de acarreo conectando el pin Carry(Out) del sumador de la parte baja (bits 0 a 7) mediante un cable directo al pin Cin (Carry In) del sumador de la parte alta (bits 8 a 15), mientras que el Cin inicial de la parte baja se vincula a un 0 constante. El uso de Splitters permite desarmar los buses unificados de 16 bits del Registro Base y del Offset en dos canales de 8 bits a la entrada de la ALU, empleando un tercer splitter a la salida para volver a unificar los resultados parciales en un bus de direcciones definitivo de 16 bits.

## 5. Memoria RAM de Datos (64K x 16b)
El bus de direcciones unificado de 16 bits viaja directamente al pin A (Address) de la memoria RAM para gestionar el acceso. Al configurar la RAM con un Address Bit Width de 16 bits, el procesador es capaz de mapear un espacio de direccionamiento plano de 65.536 casilleros de memoria (64 KB). En cuanto a la configuración de control, el pin W (Write) está conectado a un 0 lógico constante que fija la memoria en Modo Lectura para cumplir con la semántica de carga de la instrucción. Esto causa que el pin DI (Data In) quede inactivo, mientras que el pin DO (Data Out) expulsa la palabra de 16 bits almacenada en la dirección calculada hacia el registro intermedio final.
